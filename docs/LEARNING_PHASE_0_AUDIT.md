# Phase 0 learning feature audit

26 November 2026 · Phase 0 complete. Source review, guest-browser verification and isolated SQLite service verification.

## Product scope and current behavior

Smart Resume AI recommends courses and certifications from external providers. Users can track their progress and list external certifications they confirm they actually completed. Internal certificate generation, issuance, awards, document storage, codes and public verification are outside the product scope. The current implementation still performs several of these operations. This audit records the impact for owner review before any runtime, routing, storage or data change.

| User-facing state | Evidence and permitted use |
| --- | --- |
| **Recommended** | A reviewed, dated link to the genuine provider's page for that offering. Display why it fits a role or skill gap. A suggestion or a link visit contributes no qualification to a résumé. |
| **In progress** | The user explicitly records that they started. Show it in learning progress. Exclude it from earned qualifications and résumé export. |
| **Completed** | The user explicitly confirms actual completion with the external provider. Only a completed **certification** is eligible for the résumé's certifications list, after confirmation for the chosen résumé. Describe it as user-reported. Course completion or an internal assessment score alone cannot establish an external certification. |

Assessments, skill results, career guidance, privacy exports, deletion, and user-authored résumé entries have independent uses. ## Assessment ownership and grading

The submit route passes the session user and visitor identity to the grading service. Its finished-attempt branch precedes both ownership checks. On the active branch, the checks depend on both supplied and stored identifiers being present. The separate proctoring-session handler authenticates the caller but checks a candidate owner only when an existing session has a user ID. Review binding to the underlying assessment on first registration and for missing-owner states. These are source findings. No live submission or cross-account probe was performed. ## Recommended priorities

1. **Assessment ownership.** Establish the requesting owner before either an active or finished attempt can be read, graded or used to change proctoring state. The handler currently processes the result, reads snapshots for topic totals and ends the live session after the service returns. The five career-path checks exercise different handlers. This is a source finding. [Service](../src/server/db/index.ts#L3376) · [Submit handler](../src/app/api/assessments/submit/route.ts#L43)
2. **Active legacy exposure.** Review disabling new internal writes in both the server and browser, public lookup/printing and earned-qualification displays. Decide the disposition of existing links, historical rows and local storage separately. A removal, redirect, data operation or security change requires explicit approval. [Dependency and impact inventory](#legacy-certificate-dependencies-and-impact)
3. **Truthful recommendations and résumés.** Admit only actual provider offerings with dated evidence. Distinguish all three progress states. Use a user's explicitly confirmed external completion for résumé inclusion and remove the invented default year in an approved fix. [Provider and résumé findings](#external-recommendations-and-completed-qualifications)
4. **Catalog and progress integrity.** Reconcile the six SQLite and five PostgreSQL checklist seeds. Review integer progress, uniqueness, concurrent first updates and completion dates in both tracking paths. Keep the configurable assessment threshold with the attempt. [Course findings](#findings-from-the-source-review)
5. **Data safety.** Use a fresh explicitly isolated path per suite. The helper still defaults to copying the project database when the path is omitted. Email-based administrator deletion and retention of unlinked feedback text remain separate open findings. [Helper](../scripts/testDbIsolation.mjs#L34) · [Deletion](../src/server/db/index.ts#L6307)
